# Onboarding Job Progress App

A React + Vite + TypeScript onboarding flow with multi-step navigation, contextual job tracking, and real-time progress updates.

## User scenarios

### 1. Запуск обробки

- Користувач проходить перший крок і вибирає головне бажання.
- На другому кроці вводить вагу та переходить до обробки.
- Після натискання `Continue` додається `jobId`, і користувач потрапляє на крок `Step 3`.

### 2. Отримання результату

- На кроці `Step 3` UI показує круговий індикатор прогресу та статус.
- Статус і прогрес оновлюються в реальному часі з бекенду.
- Коли `status` переходить у `DONE`, робота завершується і користувач може `Reset` і повернутися на початок.

## Як працює job processing

- Коли користувач завершив введення даних, генерується або отримується `jobId`.
- У компоненті `Step3` викликається `trackJob(jobId)`.
- `useJobProgress` підключається до WebSocket-сервера і слухає подію `job_update:${jobId}`.
- Кожне оновлення з бекенду містить `{ status, progress }`.
- Статус і прогрес зберігаються в хукcі та автоматично рендеряться в UI.

## Як оновлюється статус

### WebSocket

- Основна логіка оновлення працює через WebSocket (`socket.io-client`).
- Клієнт слухає подію `job_update:${jobId}` і оновлює `progress` / `status` у стані.
- Для завершення роботи видаляється слухач після отримання `status === 'DONE'`.

### HTTP

- У цій версії компонента HTTP-післязапитів немає — весь реальний час працює через WebSocket.
- Якщо потрібна альтернатива, можна додати періодичний `polling` через HTTP для резервного оновлення.

## Архітектурні рішення

- `React Router` для кроків: `/step-1`, `/step-2`, `/step-3`.
- `JobContext` для збереження `selectedWish`, `weight`, `jobId` і `reset()`.
- `useJobProgress` для відокремленої WebSocket-логіки та реактивного оновлення стану.
- `Layout` рендерить фіксовану шапку з прогрес-баром по всій ширині екрану.
- Tailwind CSS для швидкого стилювання без додаткових CSS-файлів.
